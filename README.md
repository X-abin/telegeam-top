# Telegram Bot 兑换码批次发放系统

这是一个基于 Telegram Bot 的兑换码批次发放机器人。

## 渠道续费价值分析工具

在线地址：<https://x-abin.github.io/telegeam-top/>

这是一个基于 NewAPI `/api/channel/` 和 `/api/log/` 在线拉取数据的可视化分析页面，用于判断渠道是否值得继续续费或复充。页面会综合成功率、错误率、平均响应时间、额度消耗、模型使用分布、请求量趋势和异常请求，给出 `建议续费`、`谨慎续费`、`暂不续费` 或 `建议更换渠道` 的结论。

独立在线工具使用文档 workflow：从已登录 NewAPI 后台复制 `Cookie` 和 `New-Api-User`，填写到页面中，再通过可信代理转发到 NewAPI。浏览器不能直接设置 `Cookie` 请求头，所以 GitHub Pages 版本需要代理地址才能在线拉取渠道和日志。

页面源码位于 [`docs/index.html`](docs/index.html)，由 GitHub Pages 发布。

Cloudflare Worker 代理示例位于 [`workers/newapi-workflow-proxy.js`](workers/newapi-workflow-proxy.js)，只允许转发 `https://maolaoapi.com/api/channel/` 和 `https://maolaoapi.com/api/log/`。

核心规则：

- 用户不能通过菜单或命令主动领取兑换码。
- 所有领取行为必须通过管理员生成的专属领取链接完成。
- 每个批次都有唯一领取链接。
- 领取前必须通过九宫格目标点击人机验证。
- 同一个 Telegram 用户在同一个批次中只能领取一次。
- 用户重复打开同一领取链接时，只会返回已领取的兑换码，不会重复扣库存。
- Bot 只在私聊中响应消息和命令；在群聊中只做静默发言统计，不发送任何回复。
- Bot 会自动清理领取和配置过程中的临时提示，减少私聊消息堆叠。
- 系统记录每次领取日志，便于查询、统计和风控。

## 核心流程

管理员创建兑换码批次 → 导入兑换码 → 系统生成唯一领取链接 → 管理员分享领取链接 → 用户点击链接进入 Bot → 用户完成九宫格点击验证 → Bot 校验领取资格 → Bot 自动发放兑换码 → 系统记录领取结果。

Bot 内已经提供 `核心流程` 按钮和 `/flow` 命令，管理员可以随时查看这条流程。

Bot 内还提供 `⚙️ 默认条件` 按钮和 `/defaults` 命令，用来修改新批次的默认领取条件。

## 领取条件

每个批次都可以单独设置领取条件：

- 群发言数条件：用户在指定群聊中的普通发言数至少达到管理员设置的数字。
- 频道订阅条件：用户必须订阅指定频道或群。
- 也可以设置为无额外条件。

创建批次时，Bot 会先载入默认条件，然后让管理员通过按钮逐项调整。每一项都能单独修改，最后还会有确认页，避免直接落库。

如果你想修改后续新批次的默认条件，可以直接在 Bot 里打开 `⚙️ 默认条件` 面板修改，不需要改代码。

注意：

- 群发言条件通过一个 `💬 群发言条件` 按钮设置：先填写群 ID，再填写最低普通发言数。
- 群发言数只能统计 Bot 加入群之后收到的消息；管理员可在私聊里点击 `📊 已记录群` 或发送 `/groups` 查看可用群 ID。
- 群发言条件必须填写群聊 Chat ID，通常是负数，超级群一般是 `-100...`；不要填写管理员或用户的 Telegram User ID。
- 必须在 BotFather 关闭 Privacy Mode，Bot 才能收到并记录普通群消息。管理员可在私聊里点击 `🛡 接收状态` 或发送 `/botstatus` 查看当前状态。
- Bot 只统计普通用户的普通群消息；`/start`、`/active` 等斜杠命令不会计入发言数。
- 群发言条件使用群 ID；频道订阅条件使用频道/群订阅检测 ID，两者可以不同，需要分别设置。
- 如果需要统计普通群消息，需要在 BotFather 里关闭 privacy mode，或确保 Bot 能收到群消息。
- Bot 在群聊内不会响应任何命令，包括管理员命令，避免刷屏影响聊天。
- 频道订阅检查需要 Bot 能访问该频道或群，建议把 Bot 加入目标频道/群并授予合适权限。
- 公开频道可填写 `@channel` 或 `https://t.me/channel`。
- 私密邀请链接需要同时填写可检测的 `chat_id`，格式为 `-1001234567890 https://t.me/+xxxx`；邀请链接只用于给用户打开订阅入口，真实检测仍依赖 `chat_id`。
- 管理员也可以把目标频道或群的一条消息转发给 Bot，Bot 会尝试识别并返回可用于检测的 `chat_id`。

## 功能范围

管理员：

- 所有管理员操作都需要在 Bot 私聊中完成。
- `/admin` 打开管理员面板
- `/newbatch` 创建兑换码批次
- `/batches` 查看批次列表
- `/batch <批次编号>` 查看批次详情
- `/records` 查看最近领取记录
- `/flow` 查看核心流程
- `/groups` 查看已记录群 ID
- `/botstatus` 查看普通群消息接收状态
- `/chatid` 查看当前私聊 ID
- `/whoami` 查看自己的 Telegram User ID
- `/defaults` 查看和修改默认领取条件

用户：

- 只能通过 `https://t.me/<bot_username>?start=<batch_token>` 这样的专属链接领取
- 进入链接后需要完成九宫格目标点击验证
- 验证通过后，系统按批次规则发放兑换码

## 批次类型

`usage`：使用次数型

- 只有一个兑换码
- 多个用户领取到同一个兑换码
- 每成功领取一次，剩余次数减 1
- 次数用完后停止发放

`unique`：领完为止型

- 管理员导入多个兑换码
- 每个兑换码只发放一次
- 全部发完后停止领取

## 配置

复制 `.env.example` 为 `.env`：

```env
BOT_TOKEN=你的 Telegram Bot Token
ADMIN_IDS=管理员 Telegram user_id，多个用英文逗号分隔
BOT_USERNAME=机器人用户名，不带 @
DATABASE_PATH=data/bot.sqlite3
LOG_FILE=logs/bot.log
```

## 运行

当前版本兼容 Python 3.6，不依赖第三方库：

```bash
python3 bot.py
```

## 管理员创建批次

发送：

```text
/newbatch
```

Bot 会引导你依次填写：

1. 批次名称
2. 批次类型：`usage` 或 `unique`
3. 领取条件（按钮配置）
4. 兑换码和次数，或多行兑换码
5. 最终确认

创建完成后，Bot 会返回专属领取链接。
