# Telegram Bot 兑换码批次发放系统

这是一个基于 Telegram Bot 的兑换码批次发放机器人。

核心规则：

- 用户不能通过菜单或命令主动领取兑换码。
- 所有领取行为必须通过管理员生成的专属领取链接完成。
- 每个批次都有唯一领取链接。
- 领取前必须点击一次人机验证按钮。
- 同一个 Telegram 用户在同一个批次中只能领取一次。
- 用户重复打开同一领取链接时，只会返回已领取的兑换码，不会重复扣库存。
- 系统记录每次领取日志，便于查询、统计和风控。

## 核心流程

管理员创建兑换码批次 → 导入兑换码 → 系统生成唯一领取链接 → 管理员分享领取链接 → 用户点击链接进入 Bot → 用户点击一次验证按钮 → Bot 校验领取资格 → Bot 自动发放兑换码 → 系统记录领取结果。

Bot 内已经提供 `核心流程` 按钮和 `/flow` 命令，管理员可以随时查看这条流程。

## 功能范围

管理员：

- `/admin` 打开管理员面板
- `/newbatch` 创建兑换码批次
- `/batches` 查看批次列表
- `/batch <批次编号>` 查看批次详情
- `/records` 查看最近领取记录
- `/flow` 查看核心流程

用户：

- 只能通过 `https://t.me/<bot_username>?start=<batch_token>` 这样的专属链接领取
- 进入链接后需要点击 `点击完成验证`
- 验证通过后，系统按批次规则发放兑换码

## 批次类型

`usage`：使用次数型

- 只有一个兑换码
- 多个用户领取到同一个兑换码
- 每成功领取一次，剩余次数减 1
- 次数用完后停止发放

`unique`：领完为止型

- 管理员导入多个兑换码
- 每个兑换码只发放一次
- 全部发完后停止领取

## 配置

复制 `.env.example` 为 `.env`：

```env
BOT_TOKEN=你的 Telegram Bot Token
ADMIN_IDS=管理员 Telegram user_id，多个用英文逗号分隔
BOT_USERNAME=机器人用户名，不带 @
DATABASE_PATH=data/bot.sqlite3
LOG_FILE=logs/bot.log
```

## 运行

当前版本兼容 Python 3.6，不依赖第三方库：

```bash
python3 bot.py
```

## 管理员创建批次

发送：

```text
/newbatch
```

Bot 会引导你依次填写：

1. 批次名称
2. 批次类型：`usage` 或 `unique`
3. 兑换码和次数，或多行兑换码

创建完成后，Bot 会返回专属领取链接。
